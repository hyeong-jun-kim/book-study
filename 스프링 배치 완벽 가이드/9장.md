## 8장: ItemWriter

### ItemWriter의 역할과 개념

`ItemWriter`는 스프링 배치 처리 흐름의 **최종 출력 단계를 담당**하는 핵심 인터페이스이다.

`ItemReader`가 데이터를 읽어오는 시작점이면, `ItemWriter`는 모든 처리가 끝난 데이터를 외부 시스템이나 파일, 데이터베이스 등에 기록하는 종료점이다.

스프링 배치 2에서 청크(Chunk) 기반 처리 방식이 도입되면서 `ItemWriter`의 역할은 크게 바뀌었다. 건건이 아이템을 쓰는 방식이 아니라, 여러 아이템을 하나의 묶음(청크) 단위로 모아 **한 번에 쓰기 작업을 수행**하게 되었다.

- 동작 흐름 (그림 9-1)

1. `ItemReader`가 아이템을 하나씩 반복해서 읽는다
2. 읽어온 아이템은 `ItemProcessor`로 전달되어 데이터 변환 등의 처리를 거친다
3. 처리된 아이템들은 리스트에 계속 쌓이다가, 미리 설정된 청크 크기(EX:10개)를 채우게 된다.
4. 청크가 완성되면, 아이템이 담긴 리스트 전체가 `ItemWriter`로 전달되어 한 번의 `write`메서드 호출로 모든 데이터가 기록된다.

이러한 청크 기반 처리 방식 때문에, `ItemWriter` 인터페이스의 `write` 메서드는 단일 아이템이 아닌 **아이템의 리스트**를 파라미터로 받도록 정의되어 있다.

```java
// 예제 9-1: ItemWriter 인터페이스
package org.springframework.batch.item;

import java.util.List;

public interface ItemWriter<T> {
    void write(List<? extends T> items) throws Exception;
}
```

### FlatFileItemWriter: 텍스트 파일 생성

`FlatFileItemWriter`는 텍스트 파일 출력을 위해 스프링 배치가 기본으로 제공하는 강력한 구현체이다.

**핵심 구성 요소 (그림9-2)**  
`FlatFileItemWriter`는 크게 두 가지 핵심 컴포넌트로 구성된다.

1. `Resource`: 쓰기 작업을 수행할 대상 파일 또는 스크립트를 지정한다.
2. `LineAggregator`: `ItemReader`의 `LineMapper`와 정반대의 역할을 수행한다. 즉, **자바 객체를 파일에 쓸 한 줄의 문자열로 변환**하는 역할을 담당한다.

| 옵션                 | 타입                   | 기본값           | 설명                                                                                             |
| -------------------- | ---------------------- | ---------------- | ------------------------------------------------------------------------------------------------ |
| encoding             | String                 | "UTF-8"          | 파일의 문자 인코딩을 지정합니다.                                                                 |
| footerCallback       | FlatFileFooterCallback | null             | 파일의 마지막 아이템이 처리된 후 실행되어 푸터(footer)를 추가합니다.                             |
| headerCallback       | FlatFileHeaderCallback | null             | 파일의 첫 번째 아이템이 처리되기 전에 실행되어 헤더(header)를 추가합니다.                        |
| lineAggregator       | LineAggregator         | null (필수)      | 개별 아이템을 출력용 문자열로 변환하는 데 사용됩니다.                                            |
| lineSeparator        | String                 | 시스템 개행 문자 | 생성된 파일의 개행 문자를 지정합니다.                                                            |
| resource             | Resource               | null (필수)      | 쓰기 작업 대상 파일 또는 스트림을 지정합니다.                                                    |
| saveState            | boolean                | true             | 라이터의 상태(예: 처리한 아이템 수)를 ExecutionContext에 저장할지 여부를 지정합니다.             |
| shouldDeleteIfEmpty  | boolean                | false            | 기록할 레코드가 한 건도 없을 때 파일을 삭제할지 여부를 지정합니다.                               |
| appendAllowed        | boolean                | false            | true로 설정하면, 대상 파일이 이미 존재할 때 덮어쓰지 않고 기존 파일에 내용을 추가합니다.         |
| shouldDeleteIfExists | boolean                | true             | true로 설정하면, 쓰기 작업 대상 파일이 이미 존재할 때 해당 파일을 삭제하고 새 파일을 생성합니다. |
| transactional        | boolean                | true             | true로 설정하면, 트랜잭션이 커밋될 때까지 파일에 대한 데이터 쓰기가 지연됩니다.                  |

**파일 쓰기와 트랜잭션**  
파일 시스템은 DB와 달리 트랜잭션을 지원하지 않아 쓰기 실패 시 롤백이 불가능하다. 이 문제를 보완하기 위해 `FlatFileItemWriter`는 다음과 같이 동작한다.

- 실제 파일 쓰기 작업을 **트랜잭션이 커밋되기 직전, 가장 마지막 순간까지 지연**시킨다.
- 내부적으로 `TransactionSynchronizationAdapter`의 `beforeCommit` 메서드를 사용하여 이 메커니즘을 구현한다.
- 이를 통해, 청크 처리 중 다른 부분에서 오류가 발생하여 트랜잭션이 롤백될 경우, 파일에 데이터가 일부만 잘못 기록되는 상황을 최소화할 수 있다.

#### 활용 예제 1: 형식화된 텍스트 파일 생성

CSV 파일의 고객 데이터를 읽어, 각 고객 정보를 하나의 문장으로 형식화해 텍스트 파일로 저장하는 예제이다.

- 입력 파일 (예제 9-2:customer.csv)
  `Richard,N,Darrow,5570 Isabella Ave,St. Louis,IL,58540`
- 목표 출력 파일 (예제 9-3)
  `Richard N Darrow lives at 5570 Isabella Ave in St. Louis, IL.`
- 도메인 객체 (예제 9-4: Customer.java)

```java
public class Customer {
    private String firstName;
    private String middleInitial;
    private String lastName;
    private String address;
    private String city;
    private String state;
    private String zip;
    // ... Accessors go here
}
```

- `ItemReader` 설정 (예제 9-5)
  입력 CSV 파일을 읽기 위한 `FlatFileItemReader`를 구성

```java
@Bean
@StepScope
public FlatFileItemReader<Customer> customerFileReader(
        @Value("#{jobParameters['customerFile']}") Resource inputFile) {
    return new FlatFileItemReaderBuilder<Customer>()
            .name("customerFileReader")
            .resource(inputFile)
            .delimited()
            .names(new String[] {"firstName", "middleInitial", "lastName",
                                 "address", "city", "state", "zip"})
            .targetType(Customer.class)
            .build();
}
```

- `ItemWriter` 설정 (예제 9-6)  
  이 예제의 핵심으로 `FormatterLineAggregator`를 사용해 원하는 문장 형식으로 출력하도록 `FlatFileItemWriter`를 구성한다.

```java
@Bean
@StepScope
public FlatFileItemWriter<Customer> customerItemWriter(
        @Value("#{jobParameters['outputFile']}") Resource outputFile) {
    return new FlatFileItemWriterBuilder<Customer>()
            .name("customerItemWriter")
            .resource(outputFile)
            .formatted() // FormatterLineAggregator 사용 지정
            .format("%s %s lives at %s %s in %s, %s.") // 출력 형식 정의
            .names(new String[] {"firstName", "lastName", "address",
                                 "city", "state", "zip"}) // 형식에 매핑될 필드 순서
            .build();
}
```

```java
// 예제 9-7: FormattedTextFileJob의 전체 구성
@EnableBatchProcessing
@Configuration
public class FormattedTextFileJob {
    // ... JobBuilderFactory, StepBuilderFactory 주입 ...

    // ... customerFileReader()와 customerItemWriter() 빈은 이전과 동일 ...

    @Bean
    public Step formatStep() {
        return this.stepBuilderFactory.get("formatStep")
                .<Customer, Customer>chunk(10)
                .reader(customerFileReader(null)) // ItemReader 연결
                .writer(customerItemWriter(null)) // ItemWriter 연결
                .build();
    }

    @Bean
    public Job formatJob() {
        return this.jobBuilderFactory.get("formatJob")
                .start(formatStep()) // 시작 스텝 지정
                .incrementer(new RunIdIncrementer())
                .build();
    }
}
```

해당 잡을 실행하면, `customerFile` 파라미터로 지정된 CSV 파일을 읽어, `outputFile` 파라미터로 지정된 경로에 형식화된 문장이 담긴 텍스트 파일(formattedCustomers.txt)이 생성된다.

#### 파일 관리 고급 옵션

`FlatFileItemWriter`는 출력 파일이 이미 존재하거나, 출력이 비어있는 등 다양한 시나리오를 처리하기 위한 세부 옵션을 제공한다.

- `shouldDeleteIfEmpty(true)`: 출력이 없을 때 파일 삭제
  - 기본값: false
- `shouldDeleteIfExists(false)`: 파일이 존재할 때 덮어쓰기 방지
  - 기본값: true
- `appendAllowed(true)`: 기존 파일에 데이터 추가
  - 기본값: false

### StaxEventItemWriter: XML 파일 생성

`StaxEventItemWriter`는 STAX(Straming API for XML)를 사용해 XML 파일을 생성하는 `ItemWriter`이다.  
청크 단위로 아이템을 XML 프래그먼트로 변환해 파일에 쓰기 때문에 메모리 효율성이 좋다.  
`FlatFileItemWriter`와 유사하게, 실제 파일에 쓰는 작업을 로컬 트랜잭션에 커밋되기 직전이 수행하여 오류 발생 시 불완전하게 기록된 파일이 생성되는 문제를 방지한다.

| 옵션            | 타입               | 기본값      | 설명                                                                                                                          |
| --------------- | ------------------ | ----------- | ----------------------------------------------------------------------------------------------------------------------------- |
| marshaller      | Marshaller         | null (필수) | 아이템 객체를 XML 프래그먼트로 변환하는 데 사용됩니다.                                                                        |
| resource        | Resource           | null (필수) | 쓰기 작업을 수행할 파일 또는 스트림입니다.                                                                                    |
| rootTagName     | String             | null (필수) | 생성될 XML 문서의 최상위 루트 태그 이름을 정의합니다.                                                                         |
| headerCallback  | StaxWriterCallback | null        | 첫 번째 아이템이 처리되기 전에 실행되어 헤더 XML을 추가합니다.                                                                |
| footerCallback  | StaxWriterCallback | null        | 마지막 아이템이 처리된 후 실행되어 푸터 XML을 추가합니다.                                                                     |
| overwriteOutput | boolean            | true        | true인 경우, 출력 파일이 이미 존재하면 새 파일로 대체됩니다.<br>false이고 파일이 존재하면 `ItemStreamException`이 발생합니다. |
| encoding        | String             | "UTF-8"     | 파일의 문자 인코딩을 지정합니다.                                                                                              |
| version         | String             | "1.0"       | XML 문서의 버전을 지정합니다.                                                                                                 |

- 설정 예제: CSV 파일에서 읽은 `Customer` 객체를 XML 파일로 저장하는 예제이다. 이 과정에서는 `XStreamMarshaller`를 사용해 객체를 XML로 변환한다.

```java
// 예제 9-19: XML 출력을 위한 StaxEventItemWriter 구성
@Bean
@StepScope
public StaxEventItemWriter<Customer> xmlCustomerWriter(
        @Value("#{jobParameters['outputFile']}") Resource outputFile) {

    // XML 태그 이름을 'com.apress.springbatch...Customer' 대신 'customer'로 지정하기 위한 설정
    Map<String, Class> aliases = new HashMap<>();
    aliases.put("customer", Customer.class);

    XStreamMarshaller marshaller = new XStreamMarshaller();
    marshaller.setAliases(aliases);

    return new StaxEventItemWriterBuilder<Customer>()
            .name("customerItemWriter")
            .resource(outputFile)
            .marshaller(marshaller) // JAXB, XStream 등의 Marshaller 설정
            .rootTagName("customers") // XML 최상위 태그 이름
            .build();
}
```

### 데이터베이스 기반 ItemWriter

### JdbcBatchItemWriter

`JdbcTemplate`의 batch update 기능을 활용해 성능을 극대화하는 `ItemWriter`이다. 청크 내의 모든 INSERT/UPDATE 문을 한 번의 네트워크 호출로 데이터베이스에 전송한다.

- **예제 시나리오**: CSV 파일의 고객 데이터를 읽어 데이터베이스의 `Customer` 테이블에 저장한다.

PreparedStatement 방식

- ItemPreparedStatementSetter 인터페이스:
  이 인터페이스는 setValues라는 단 하나의 메서드를 가진다. 이 메서드 안에서 아이템 객체의 필드 값을 추출하여 PreparedStatement의 각 ? 파라미터에 순서대로 바인딩하는 코드를 작성해야 한다.

```java
// 예제 9-24: ItemPreparedStatementSetter 인터페이스
package org.springframework.batch.item.database;
import java.sql.PreparedStatement;
import java.sql.SQLException;

public interface ItemPreparedStatementSetter<T> {
    void setValues(T item, PreparedStatement ps) throws SQLException;
}
```

```java
// 예제 9-25: CustomerItemPreparedStatementSetter 구현
public class CustomerItemPreparedStatementSetter implements ItemPreparedStatementSetter<Customer> {
    public void setValues(Customer customer, PreparedStatement ps) throws SQLException {
        ps.setString(1, customer.getFirstName());
        ps.setString(2, customer.getMiddleInitial());
        ps.setString(3, customer.getLastName());
        ps.setString(4, customer.getAddress());
        ps.setString(5, customer.getCity());
        ps.setString(6, customer.getState());
        ps.setString(7, customer.getZip());
    }
}
```

**PreparedStatement 방식의 전체 잡(Job) 구성**

```java
// 예제 9-27: JDBC 데이터베이스에 쓰기 작업을 수행하도록 구성한 잡
@Configuration
public class JdbcFormatJob {
    // ... JobBuilderFactory, StepBuilderFactory ...

    // ... customerFileReader() 빈은 이전과 동일 ...

    // 예제 9-26: jdbcBatchWriter의 구성
    @Bean
    public JdbcBatchItemWriter<Customer> jdbcCustomerWriter(DataSource dataSource) {
        return new JdbcBatchItemWriterBuilder<Customer>()
                .dataSource(dataSource)
                .sql("INSERT INTO CUSTOMER (first_name, " +
                     // ...
                     "zip) VALUES (?, ?, ?, ?, ?, ?, ?)")
                .itemPreparedStatementSetter(new CustomerItemPreparedStatementSetter())
                .build();
    }

    @Bean
    public Step jdbcFormatStep() throws Exception {
        return this.stepBuilderFactory.get("jdbcFormatStep")
                .<Customer, Customer>chunk(10)
                .reader(customerFileReader(null))
                .writer(jdbcCustomerWriter(null))
                .build();
    }

    @Bean
    public Job jdbcFormatJob() throws Exception {
        return this.jobBuilderFactory.get("jdbcFormatJob")
                .start(jdbcFormatStep())
                .build();
    }
}
```

**이름 기반 파라미터(Named Parameter) 방식**  
`?` 플레이스 홀더 대신 `:firstName`과 같이 이름 기반 파라미터를 사용하는 방식이다.  
파라미터의 순서에 신경 쓸 필요가 없고, 가독성이 높아 **더 안전하고 선호되는 방법**이다.

`JdbcBatchItemWriterBuilder`의 `.beanMapped()` 메서드를 호출하는 것만으로 `BeanPropertyItemSqlParameterSourceProvider`가 적용되어, 별도의 매핑 코드 없이 간결하게 구성할 수 있다.

```java
// 예제 9-30: BeanPropertyItemSqlParameterSourceProvider를 사용하는 JdbcBatchItemWriter
@Bean
public JdbcBatchItemWriter<Customer> jdbcCustomerWriter(DataSource dataSource) {
    return new JdbcBatchItemWriterBuilder<Customer>()
            .dataSource(dataSource)
            .sql("INSERT INTO CUSTOMER (first_name, ..., zip) " +
                 "VALUES (:firstName, ..., :zip)") // 이름 기반 파라미터 사용
            .beanMapped() // 아이템 프로퍼티와 SQL 파라미터를 자동으로 매핑
            .build();
}
```

### 스프링 데이터(Spring Data)기반 ItemWriter

### MongoItemWriter: 몽고DB에 쓰기

`MongoItemWriter`는 고성능 문서 지향 데이터베이스인 몽고DB(MongoDB)의 컬렉션에 객체를 문서 형태로 저장한다.

- 도메인 객체 수정
  - 몽고DB는 기본적으로 ID로 `String` 타입을 사용하므로, 도메인 객체의 ID 필드를 `long`에서 `String`으로 변경해야한다.

```java
// 예제 9-38: 몽고DB용 Customer
public class Customer implements Serializable {
    @Id
    private String id; // ID 타입을 String으로 변경
    private String firstName;
    // ...
}
```

- MongoItemWriter 구성
  - `MongoItemWriterBuilder`를 사용하며, 스프링 부트가 자동으로 구성해주는 MongoOperations 인스턴스와 쓰기 작업을 수행할 `collection` 이름을 지정해야 한다.

```java
// 예제 9-40: mongoFormatJob 구성
@Configuration
public class MongoImportJob {
    // ... Job, Step 빌더 팩토리, ItemReader ...

    @Bean
    public MongoItemWriter<Customer> mongoItemWriter(MongoOperations mongoTemplate) {
        return new MongoItemWriterBuilder<Customer>()
                .collection("customers") // 저장할 컬렉션 이름
                .template(mongoTemplate) // MongoOperations 템플릿 주입
                .build();
    }

    @Bean
    public Step mongoFormatStep() throws Exception {
        return this.stepBuilderFactory.get("mongoFormatStep")
                .<Customer, Customer>chunk(10)
                .reader(customerFileReader(null))
                .writer(mongoItemWriter(null))
                .build();
    }

    // ... Job 구성 ...
}
```

- 트랜잭션 처리: 몽고DB는 ACID 트랜잭션을 지원하지 않기 때문에, 스프링 배치는 몽고 DB를 파일과 같은 비트랜잭션 데이터 저장소로 취급한다.
- 즉, 실제 쓰기 작업을 커밋 직전까지 버퍼링하고 가장 마지막 순간에 수행하여 데이터 정합성을 최대한 보장한다.

### 그 밖의 출력 방식을 위한 ItemWriter

파일과 데이터베이스 외에, 이미 존재하는 서비스 호출, JMS 메시지 전송, 이메일 발송 등을 위한 ItemWriter도 제공된다.

### ItemWriterAdapter: 기존 서비스 재사용

이미 운영 환경에서 안정적으로 사용 중인 기존 스프링 서비스(Service)를 `ItemWriter`로 재사용할 수 있도록 해주는 어댑터이다.  
이는 새로운 버그 발생 가능성을 줄이고 개발 시간을 단축하는 효과적인 방법이다.

- **동작 방식**: `ItemWriterAdapter`는 내부적으로 위임 패턴을 사용한다. `write` 메서드가 호출되면, 전달받은 아이템 리스트를 순회하여 **각 아이템에 대해 지정된 서비스의 메서드를 한 번씩 호출**한다.
- **핵심 제약사항**: 호출하려는 서비스의 메서드는 반드시 **단 하나의 파라미터**만 가져야 하며, 그 파라미터의 타입은 처리 중인 아이템의 타입과 일치해야한다.
- **구성 요소**
  - `targetObject`: 호출할 메서드를 가지고 있는 스프링 빈(서비스 객체)
  - `targetMethod`: 각 아이템을 처리할 때 호출할 메서드 이름

설정 예제

```java
// 예제 9-53: CustomerService
@Service
public class CustomerService {
    public void logCustomer(Customer cust) {
        System.out.println("I just saved " + cust);
    }
}
```

```java
// 예제 9-54: ItemWriterAdapter 구성
@Bean
public ItemWriterAdapter<Customer> itemWriter(CustomerService customerService) {
    ItemWriterAdapter<Customer> customerItemWriterAdapter = new ItemWriterAdapter<>();
    customerItemWriterAdapter.setTargetObject(customerService); // 서비스 객체 설정
    customerItemWriterAdapter.setTargetMethod("logCustomer"); // 호출할 메서드 이름 설정
    return customerItemWriterAdapter;
}
```

### PropertyExtractingDelegatingItemWriter: 아이템의 속성을 추출하여 서비스 호출

`ItemWriterAdapter`는 아이템 객체 전체를 서비스에 전달해야 하는 제약이 있다.  
만약 기존 서비스 메서드가 객체 전체가 아닌, 객체의 **특정 필드 값들만** 파라미터로 받는다면 어떻게 해야할까? 이럴 때 `PropertyExtractingDelegatingItemWriter`를 사용한다.

- **핵심 구성 요소**:
  - `targetObject`: 호출할 서비스 객체.
  - `targetMethod`: 호출할 메서드 이름.
  - `fieldsUsedAsTargetMethodArguments`: 추출할 필드 이름의 배열. 이 배열의 순서는 서비스 메서드의 파라미터 순서와 반드시 일치해야 합니다.

```java
// 예제 9-56: logAddress() 메서드를 가지고 있는 CustomerService
@Service
public class CustomerService {
    public void logCustomerAddress(String address, String city,
                                 String state, String zip) {
        System.out.println(
            String.format("I just saved the address: \n%s\n%s, %s\n%s",
                          address, city, state, zip));
    }
    // ...
}
```

```java
// 예제 9-57: PropertyExtractingDelegatingItemWriter 구성
@Bean
public PropertyExtractingDelegatingItemWriter<Customer> itemWriter(
        CustomerService customerService) {
    PropertyExtractingDelegatingItemWriter<Customer> itemWriter =
        new PropertyExtractingDelegatingItemWriter<>();

    itemWriter.setTargetObject(customerService);
    itemWriter.setTargetMethod("logCustomerAddress");

    // 아이템에서 추출할 필드들을 순서대로 지정
    itemWriter.setFieldsUsedAsTargetMethodArguments(
        new String[] {"address", "city", "state", "zip"});

    return itemWriter;
}
```

### JmsItemWriter: JMS 목적지로 메시지 전송

`JmsItemWriter`는 처리된 아이템을 JMS(Java Messaging Service)를 통해 메세지 큐 또는 토픽으로 전송하는 역할을 한다. 이를 통해 다른 시스템과 비동기적으로 데이터를 연동할 수 있다.

- 예제 시나리오 (그림 9-6):
  - 스텝 1: `customer.csv` 파일을 읽어(`FlatFileItemReader`), 각 `Customer` 아이템을 JmsItemWriter를 통해 ActiveMQ 큐에 메시지로 보낸다.
  - 스텝 2: ActiveMQ 큐에서 메시지를 다시 읽어와(`JmsItemReader`), `StaxEventItemWriter`를 통해 XML 파일로 저장하여 최종 결과를 확인합니다.

```java
// 예제 9-60: JMS 리소스 구성
@Bean
public MessageConverter jacksonJmsMessageConverter() {
    MappingJackson2MessageConverter converter = new MappingJackson2MessageConverter();
    converter.setTargetType(MessageType.TEXT);
    converter.setTypeIdPropertyName("_type");
    return converter;
}

@Bean
public JmsTemplate jmsTemplate(ConnectionFactory connectionFactory) {
    CachingConnectionFactory cachingConnectionFactory =
        new CachingConnectionFactory(connectionFactory);
    cachingConnectionFactory.afterPropertiesSet();

    JmsTemplate jmsTemplate = new JmsTemplate(cachingConnectionFactory);
    jmsTemplate.setDefaultDestinationName("customers"); // 기본 목적지 큐 이름
    jmsTemplate.setReceiveTimeout(5000L);
    return jmsTemplate;
}
```

```java
// 예제 9-62: JmsItemReader/JmsItemWriter와 이를 사용하는 잡 구성
@Bean
public JmsItemReader<Customer> jmsItemReader(JmsTemplate jmsTemplate) {
    return new JmsItemReaderBuilder<Customer>()
            .jmsTemplate(jmsTemplate)
            .itemType(Customer.class)
            .build();
}

@Bean
public JmsItemWriter<Customer> jmsItemWriter(JmsTemplate jmsTemplate) {
    return new JmsItemWriterBuilder<Customer>()
            .jmsTemplate(jmsTemplate)
            .build();
}

// -- 스텝 1 구성 --
@Bean
public Step formatInputStep() throws Exception {
    return this.stepBuilderFactory.get("formatInputStep")
            .<Customer, Customer>chunk(10)
            .reader(customerFileReader(null)) // 파일 리더
            .writer(jmsItemWriter(null)) // JMS 라이터
            .build();
}

// -- 스텝 2 구성 --
@Bean
public Step formatOutputStep() throws Exception {
    return this.stepBuilderFactory.get("formatOutputStep")
            .<Customer, Customer>chunk(10)
            .reader(jmsItemReader(null)) // JMS 리더
            .writer(xmlOutputWriter(null)) // XML 라이터
            .build();
}

// -- 잡 구성 --
@Bean
public Job jmsFormatJob() throws Exception {
    return this.jobBuilderFactory.get("jmsFormatJob")
            .start(formatInputStep())
            .next(formatOutputStep()) // 스텝 1 -> 스텝 2 순차 실행
            .build();
}
```
